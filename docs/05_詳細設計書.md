# 05 詳細設計書

## 1. 認証（security.py・routers/auth.py）

| 項目 | 仕様 |
| --- | --- |
| パスワード | Argon2（argon2-cffi の初期設定）。10〜128 文字、数字だけ・英字だけは不可。ログイン時に古い設定のハッシュなら作り直す |
| ログイン | メールアドレスは前後の空白を取り、大文字小文字を区別しない。失敗の理由（メールが違う・パスワードが違う）は同じメッセージ。ユーザーがいないときもダミーのハッシュを検証して、応答時間で見分けられないようにする |
| ロック | 続けて 5 回失敗すると 15 分ロック（ロック中は正しいパスワードでも入れない）。成功で回数を 0 に。管理者の再設定で解除 |
| セッション | `secrets.token_urlsafe(32)` を Cookie に、SHA-256 を DB に保存。有効 12 時間。ログインのたびに作り直す（前のセッションは消す） |
| Cookie | `crm_session`、HttpOnly、SameSite=Lax、Path=/、Secure は `.env` の COOKIE_SECURE（HTTPS で公開するときに true） |
| 切れるとき | ログアウト、本人のパスワード変更（ほかの端末）、管理者の再設定、権限・使用中の変更 |
| CSRF | 書き換えのメソッドは `X-Requested-With: crm-app` が必須。CORS を許可していないので、ほかのサイトからはこのヘッダーを付けて送れない。SameSite=Lax でもほかのサイトからの POST に Cookie が付かない |

## 2. 入力の整え（schemas.py）

- 文字：前後の空白を取る。全角の英数字・半角カナだけを直す（「（）」などの全角の記号はそのまま）。制御文字はエラー
- メール：小文字にし、`xxx@xxx.xx` の形か確かめる
- 電話：全角数字・各種のダッシュを直し、`0` から始まる 10〜11 桁（ハイフン可）か `+` 国番号
- 金額：0〜1 兆円の整数。日付：`YYYY-MM-DD`
- 知らない項目は 422（`extra="forbid"`）
- 入力の誤りは `main.py` で日本語にし、項目名（`field`）と一緒に返す。画面は入力欄の下に出す

## 3. 権限（permissions.py）

| 操作 | 管理者 | マネージャー | メンバー |
| --- | --- | --- | --- |
| 顧客・案件・タスクを見る | ○ | ○ | ○ |
| 顧客・案件を作る | ○ | ○ | ○（担当者は自分だけ） |
| 顧客・案件を変える | ○ | ○ | 自分が担当のものだけ |
| 担当者をほかの人にする | ○ | ○ | × |
| タスクを作る | ○ | ○ | 自分が担当の案件、または担当者を自分にする |
| タスクを変える | ○ | ○ | タスクの担当者が自分、または案件の担当者が自分 |
| 削除 | ○ | ○ | × |
| 受注・失注を進行中に戻す | ○ | ○ | × |
| 進み具合を報告する | ○ | ○ | タスクを変えられる人（担当者・案件の担当者） |
| チームの状況 | ○ | ○ | × |
| 操作履歴 | ○ | ○ | ×（ダッシュボードの「最近の動き」は自分の操作だけ） |
| ユーザー管理 | ○ | × | × |

API は必ず「データを読む → 権限を判定 → 変更」の順。URL の番号を書き換えても、判定は読んだデータの担当者で行うので他人のデータは変えられない。

## 4. ステータスの決まり

| 対象 | 決まり |
| --- | --- |
| 案件 | 作成時はいったん「見込み」で作ってから指定のステータスにする。受注・失注にすると `closed_at` に今の日時、進行中に戻すと `closed_at` を空に（DB の CHECK でも同じ決まり）。閉じた案件を戻せるのはマネージャー以上 |
| タスク | 完了にすると `completed_at` に今の日時、ほかに戻すと空に（DB の CHECK でも同じ）。一覧の「完了にする」「元に戻す」（未着手へ）と選択欄は `PATCH /status` を使う |
| 開始日 | 案件・タスクとも必須（DB は NOT NULL）。省いたときの決め方と、終わりの日が開始日より前でないかの確認は `common.resolve_period` に 1 か所でまとめ、DB の CHECK でも守る |

## 5. 楽観的ロック

`version` を持つ表（顧客・案件・タスク）は、PUT・PATCH で送られた `version` が DB と同じときだけ保存し、`version` を 1 増やす。
違えば 409「ほかの人が先に更新しました…」。画面は最新を読み直すよう案内する。

## 6. 削除

顧客・案件・タスクは `deleted_at` を入れる論理削除。一覧・詳細・集計は `deleted_at IS NULL` だけを見る。

- 顧客：生きている案件が 1 件でもあれば 409
- 案件：その案件のタスクもまとめて論理削除し、件数を操作履歴に書く

## 7. 操作履歴（audit.py）

- 追加・変更・削除・ログイン・ログアウト・ログイン失敗・パスワード変更／再設定を記録
- 変更は、変わった項目だけ `{項目: [前, 後]}`。パスワード・ハッシュは記録しない
- 業務の変更と同じトランザクションで書く（保存に失敗したら履歴も残らない。ログイン失敗だけは失敗回数と一緒に確定する）
- 読む API だけで、変更・削除の API はない

## 8. ダッシュボード（routers/dashboard.py）

| 項目 | 計算 |
| --- | --- |
| 進行中の案件・見込み金額 | 見込み・提案中・交渉中の件数と金額の合計 |
| 今月の受注 | 受注の `closed_at`（日本時間）が今月の金額の合計 |
| 受注率 | 受注 ÷（受注＋失注）。閉じた案件がなければ「—」 |
| 月別の受注金額 | 直近 6 か月。日本時間の月で集計（`timezone('Asia/Tokyo', closed_at)`） |
| 期限切れ | 完了でなく、期限が今日（日本時間）より前。カードの件数はマネージャー以上はチーム全体、メンバーは自分が担当のものだけ |
| 締める予定 | 進行中で、受注予定日が 30 日以内（過ぎたものも含む） |

## 9. エラーとログ（main.py）

- `AppError`（400/401/403/404/409）：メッセージをそのまま返す
- 想定外の例外：受付番号（8 桁）だけを返し、トレースバックを `logs/app.log`（1MB×5）へ
- すべての返事に `X-Content-Type-Options: nosniff`・`X-Frame-Options: DENY`・`Referrer-Policy: same-origin`・CSP（`default-src 'self'`、スクリプトは同じサイトのファイルだけ）。API は `Cache-Control: no-store`

## 10. 画面（frontend）

- `lib/api.ts`：fetch の共通処理（Cookie を送る・CSRF ヘッダー・エラーを `ApiError` に・401 ならログイン画面へ）
- `lib/auth.tsx`：ログイン状態（`/api/auth/me`）。ログイン・ログアウトでは前の人のデータを残さない
- TanStack Query で一覧を保存し、保存したら関係する一覧・ダッシュボード・履歴を読み直す
- 絞り込みの条件は URL のパラメータに持つ（`useFilters`）。条件を変えたら 1 ページ目に戻す
- 明るさは `localStorage` に保存。最初の表示のちらつきを防ぐため、`public/theme-init.js`（外部ファイル。CSP でインラインのスクリプトは使わない）で読み込みの前に決める
- ダッシュボードはグラフの部品が大きいので、開いたときに読み込む（コード分割）

## 11. 予定表（routers/schedule.py・pages/Schedule.tsx）

- 案件の帯は「開始日 → 受注予定日」（受注予定日がなければ開始日の 1 日だけで、右端を点線にする）、タスクの帯は「開始日 → 期限」
- 表示の範囲と期間が重なる案件だけを返す（`start_date <= 範囲の終わり` かつ `coalesce(受注予定日, 開始日) >= 範囲の始まり`）。タスクはその案件のものをまとめて 1 回で読む（N+1 にしない）
- 「自分の」は、担当の案件に加えて、自分が担当のタスクがある案件も出す（メンバーがほかの人の案件で動いているときも見えるように）
- 画面は CSS の grid と `%` の位置で描く（グラフの部品を足さない）。左の名前の列は横にスクロールしても残す。土日の色は帯の下、今日の線は帯の上に重ねる
- 範囲の外にある帯は「← 10/28 まで」「12/3 から →」のように、どちらにあるかだけを出す
- 日付の計算は `YYYY-MM-DD` の文字列を UTC で計算し、PC の時差で日がずれないようにする

## 12. 期限のお知らせ（components/Reminder.tsx・lib/reminder.ts）

- ログイン後の最初の画面で、`GET /api/tasks?mine=true&status=todo&status=doing&due_to=今日＋N日` を読み、1 件以上あればダイアログを出す（期限切れと N 日以内に分ける）
- 同じタブで出すのは 1 回だけ（`sessionStorage` にだれに出したかを保存し、ログインし直したら消す）
- 音はファイルを使わず Web Audio で 2 回鳴らす。ブラウザが音を止めているときは画面だけ
- 設定（出すか・何日前から・音）は `localStorage` に保存。壊れた値は初めの設定に戻す（秘密の情報は保存しない）

## 13. 進み具合の報告（routers/tasks.py の report・components/Report.tsx）

- 報告は「進み具合（10% きざみ）」「見通し（予定どおり／遅れそう）」「ひとこと」。省いた項目は今のまま（期限のお知らせのボタンは見通しだけを送る）
- 状態とそろえる：完了にすると 100%・見通しを消す、未着手に戻すと 0%、完了から対応中に戻すと 90%、未着手のまま 1% 以上を報告すると対応中にする
- 楽観的ロック（version）を使い、操作履歴に「進み具合を報告（50%・遅れそう）：ひとこと」と、変わった項目の前後を残す
- 期限のお知らせのダイアログで見通しを押したあと、一覧を読み直しても、ダイアログを開き直したり音を鳴らし直したりしない

## 14. チームの状況（routers/team.py・pages/Team.tsx）

- 管理者とマネージャー（`is_manager`）だけ。メンバーは API が 403、画面はダッシュボードへ戻し、メニューにも出さない
- メンバーごとの数は 1 回の集計（`count(*) FILTER (WHERE ...)` を担当者でまとめる）で出す
- 「止まっている」：未完了で、最後の報告（なければ最後の変更）から 7 日以上たつ（`STALE_DAYS`。タスクの一覧の `stale` と同じ条件を共有）
- 数字はタスクの一覧へのリンク（`/tasks?assignee_id=3&overdue=1` など）
