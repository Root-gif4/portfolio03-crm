そのほかの対策：

- Cookie：HttpOnly・SameSite=Lax・Path=/。HTTPS で公開するときは `.env` の `COOKIE_SECURE=true`
- CSRF：書き換えは独自ヘッダー必須（A07）。CORS は許可しない
- セッション固定攻撃：ログインのたびにセッションを作り直す。パスワード変更・権限変更・使用停止でログインを切る（A06・A12）
- クリックジャッキング：`X-Frame-Options: DENY`・`frame-ancestors 'none'`
- 監査：操作履歴は追加だけ。変わった項目の前と後、IP を記録（パスワードは記録しない）
- サーバーは `127.0.0.1` だけで待ち受け（ほかの PC からつながらない）

追加機能（開始日・予定表・期限のお知らせ、2026-11-23）の確認：

- 予定表の API はログイン必須（A08 に追加）で、読むだけ。閲覧はチームで共有する決まり（要件定義書）どおり。期間は 370 日・件数は 200 件までにして、重い問い合わせを防ぐ
- 開始日は Pydantic で日付の形を確かめ、期限との前後は API と DB の CHECK の両方で守る（B25・B26）
- お知らせの設定は `localStorage`、出したかどうかは `sessionStorage` に入れるが、中身は日数と「はい／いいえ」と利用者の番号だけで、秘密の情報は入れない
- 新しく使ったライブラリはない（音は Web Audio、グラフは CSS）

進み具合の報告・チームの状況（2026-11-23）の確認：

- 報告の API はタスクを変えられる人だけ（他人は 403、B30）。進み具合・見通しは Pydantic と DB の CHECK の両方で範囲を守る（B32）。ひとことは 200 文字までで、React がエスケープして表示する
- チームの状況は管理者・マネージャーだけ（API で 403、B31。画面のメニューとページも出さない、F18）
- 新しいライブラリはない

公開する前に必要なこと（今回は対象外）：HTTPS、見本ユーザーの削除・パスワード変更、`COOKIE_SECURE=true`、DB のバックアップ、/security-review。
